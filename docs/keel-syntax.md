## 2. Синтаксис (грамматика v0)

C-подобный, с отличиями: тип пишется после имени (`fuel int`, как в Valen),
нет `->` (авто-разыменование), нет объявлений в стиле C (`int *x`),
иммутабельность по умолчанию, `mut` — единственное слово для изменяемости.

### 2.1. Лексика

```
комментарий  = "//" до конца строки | "/*" ... "*/"
идентификатор= [A-Za-z_][A-Za-z0-9_]*
ключевое     = let mut fn struct in return if else while for break continue
               true false new
целое        = [0-9]+ ("_" [0-9]+)*     ; без суффиксов, тип выводится
вещественное = [0-9]+ "." [0-9]+
строка       = '"' ( любой символ кроме " и \ | "\\" escape )* '"'
оператор     = + - * / % == != < > <= >= && || ! = & | . , ; : ( ) [ ] { } < >
```

Тип целого по умолчанию — `int` (64-битный знаковый). Суффиксов нет: это
убирает шум, а выводимость типов делает их ненужными. Тип `float` — 64-битный
double, отличается от `int` только литералом с точкой.

Унарный минус — часть выражения, не отдельный токен.

### 2.2. Объявления

```
program      = item*

item         = struct_decl | func_decl | import_decl

import_decl  = "import" path ";"                  ; v1
struct_decl  = "struct" ident generic_params? "{" field* "}"
field        = ident type ";"
func_decl    = "fn" ident generic_params? "(" param* ")" type? mut_clause? block
generic_params = "<" ident ("," ident)* ">"

param        = ident type "mut"?                    ; обычный параметр
              | ident "in" path "mut"?             ; параметр-внутри
path         = ident ( "." ident | "[" "]" )*      ; путь группы

mut_clause   = "mut" "(" path ("," path)* ")"      ; контракт мутации
```

**Тип параметра записывается после имени**, как у Valen: `world &World`,
`count int`. Порядок `&World world` не принимается.

**`mut` на параметре** означает «эта функция изменяет то, что находится
внутри этого параметра»:

```
fn spawn(world &World mut, e Entity) { ... }   // меняет содержимое world
fn step(world &World, entity in world.entities[] mut) { ... }
```

Это **декларация**, а не разрешение: компилятор проверяет, что тело функции
действительно не меняет ничего вне объявленного, иначе ошибка. Вызывающий
после вызова инвалидирует свои ссылки внутрь указанных путей.

**Параметр-внутри** (`ident in path`) — ключевая конструкция. `entity in
world.entities[] mut` читается как «`entity` — ссылка на один из элементов
`world.entities`, и мы можем его менять». Компилятор выводит путь из тела
функции, поэтому в обычном коде писать `in` не нужно — только в сигнатуре,
где тела нет.

**`mut`-контракт** — что функция модифицирует:

```
fn push(self &Vec<T>) mut(self) { ... }
fn step(world &World, entity in world.entities[] mut) { ... }   ; синтаксический сахар
```

Второй вариант короче: `mut` на параметре-внутри означает то же самое, что
`mut(<путь параметра>)`. Путь вычисляется: `entity in world.entities[]` →
мутируется `world.entities[]`.

`mut` в контракте — не часть типа ссылки. Тип ссылки один: `&T`.

### 2.2.1. Методы и `impl`-блоки

`impl Тип { ... }` объединяет функции, относящиеся к типу:

```
impl Point {
    fn new(x int, y int) Point { ... }        // ассоциированная функция
    fn sum(self &Point) int { ... }           // метод
    fn shift(self &Point) mut(self) { ... }   // метод, меняющий объект
}
```

**Два вида функций различаются первым параметром:**

| Первый параметр | Что это | Вызов |
|---|---|---|
| `self &Тип` или `self Тип` | метод | `объект.имя(args)` |
| нет `self` | ассоциированная функция | `Тип::имя(args)` |

**`self` — обычный параметр.** На него действуют те же правила владения,
что и на любой другой: `self &Point` — ссылка, `self Point` — перемещение,
`mut(self)` — контракт изменения. Никакого особого статуса у `self` нет.

**Неявное взятие ссылки.** Если метод объявлен как `self &Point`, а
вызывается на значении (`p.sum()`), компилятор передаёт адрес сам:
`p.sum()` читается как `Point::sum(&p)`. Писать `(&p).sum()` не нужно.

**Право писать — от контракта, а не от вида `self`.** Метод со `self
&Point` без `mut(self)` писать не может — ровно как свободная функция.
Ошибка та же: «изменяет ..., но не объявляет это в mut-контракте».

**Вызов мутатора требует `mut` у владельца.** Если функция или метод
меняет путь, владелец этого пути должен быть объявлен `mut` — иначе
неизменяемая переменная менялась бы в обход правил. Это относится и к
прямой записи (`p.x = 1`), и к вызову (`p.shift()`, `shift(&p)`). Rust
запрещает второе как E0596 («cannot borrow as mutable, as it is not
declared as mutable»); Keel ловит то же самое.

| Что написано | Результат |
|---|---|
| `let p = ...; p.x = 1;` | ошибка: `p` не объявлен как `mut` |
| `let p = ...; p.shift();` | ошибка: `p` не объявлен как `mut` |
| `let p = ...; shift(&p);` | ошибка: `p` не объявлен как `mut` |
| `let p = ...; p.sum();` | ок — читатель ничего не меняет |
| `let mut p = ...; p.shift();` | ок |

**`self Point` вместо `self &Point`** — объект перемещается в метод, как
любой параметр по значению. Второй вызов невозможен: «`p` уже перемещён».
Годится для методов, которые забирают объект насовсем; для чтения и
изменения нужен `&Point`.

**Когда `self Т` уместен.** Только для методов, которые **потребляют**
объект: превращают его в другое значение, распаковывают, кладут внутрь
структуры. Имя такого метода должно это подчёркивать:

```
impl User {
    fn into_name(self User) string { return self.name; }   // забирает
    fn renamed(self User) User { ... }                     // забирает и отдаёт новое
}
```

Правило простое: **`get_*`, `sum`, `len`, `is_*` — всегда `&`.** Если метод
начинается с «получить», «посчитать», «проверить», он не имеет права
забирать объект.

**Проверка типа для параметра по значению.** `take(&u)` там, где ждут
`User`, — ошибка: `параметр `u` ожидает `User`, получен `&User``. Обратное
тоже: `take(u)` для `u &User` даёт `параметр ожидает ссылку`. Обе ошибки
ловятся в Keel, а не всплывают в сгенерированном C.

**Мутация своей копии не требует `mut` у вызывающего.** Параметр по
значению перемещён в функцию, поэтому `fn bumped(u User mut)` можно
вызвать как `bumped(u)` при `let u` — `u` всё равно уходит. Требовать
`let mut u` здесь было бы бессмысленно: менять его всё равно больше некому.

**Методы разных типов не сталкиваются.** В сгенерированном C метод
получает имя `k_Тип_метод`, поэтому `Point::get` и `Box::get` — разные
функции. Это важно: в C имена плоские, и без квалификации один метод
затёр бы другой.

**Что в `impl` пока нельзя:** дженерики (`impl Vec<T>`), методы для
встроенных типов, наследование/трейты. Это отдельные волны.

### 2.3. Типы

```
type        = base_type ("<" type ("," type)* ">")?
base_type   = "int" | "float" | "string" | "bool" | "void"
            | ident                          ; имя структуры или enum
            | "&" type                       ; ссылка
            | "[" type ";" int "]"            ; массив фиксированного размера
            | "[" type "]"                    ; срез (v1)
```

Ссылка — всегда `&T`, без `&mut`. Изменяемость определяется не типом
ссылки: см. п. 2.5.1.

**Почему тип после имени, а не `x: int`.** Это сознательный выбор, а не
особенность. Keel пишет `let fuel int = 5;` — как Go (`var x int`), а не
как Rust/TypeScript/Kotlin (`x: int`). Рассмотрены оба варианта:

- **За `x int`**: согласие с Go (второй по популярности стиль
  объявлений); отличие Keel от других языков — модель владения, а не
  синтаксис; добавление двоеточия дало бы три разные формы записи типов
  (объявление, параметр функции, параметр-внутри) вместо одной.
- **Против**: привычность — Rust, TypeScript, Kotlin, Swift и Pascal
  используют двоеточие, и новичку из любого из них придётся объяснять
  порядок.

Если синтаксис когда-нибудь будут менять, менять надо целиком и сразу:
точечно вставлять двоеточие нельзя. Двоеточие в лексере Keel свободно —
оно есть, но не используется.

Встроенные контейнеры: `Vec<T>`, `Option<T>`, `Result<T, E>`, `String`,
`HashMap<K, V>` — это обычные структуры в стандартной библиотеке, а не
особые формы языка. `Vec<T>` пишется через обобщённый синтаксис.

### 2.4. Выражения

```
expr        = or_expr

or_expr     = and_expr ("||" and_expr)*
and_expr    = cmp_expr ("&&" cmp_expr)*
cmp_expr    = add_expr (("==" | "!=" | "<" | ">" | "<=" | ">=") add_expr)?
add_expr    = mul_expr (("+" | "-") mul_expr)*
mul_expr    = unary (("*" | "/" | "%") unary)*
unary       = ("!" | "-") unary | postfix
postfix     = primary ("." ident args? | "[" expr "]" | "(" args ")")*
primary     = literal | ident | "&" unary | "(" expr ")" | "[" expr ("," expr)* "]"
             | ident "{" args "}"              ; вызов конструктора структуры
args        = (expr ("," expr)*)?
```

Приоритеты как в C: `||` < `&&` < сравнения < `+ -` < `* / %` < унарные.

**Вызов метода и доступ к полю — одна синтаксическая форма.** `x.field`
читает поле, `x.method(args)` вызывает метод. Различаются по наличию скобок,
как в Valen. Авто-разыменование: `x.field` работает и для `x: &T`, и для
`x: T`.

**Вызов конструктора** — `Name(args)`, как в Valen, а не `Name { field: val }`.
Поля задаются по порядку объявления. Именованные аргументы — v1.

**`&expr`** — взятие ссылки. Тип результата — `&T` плюс скрытый путь,
который компилятор выводит. Явное указание пути в коде не требуется нигде,
кроме сигнатур функций.

**Индексация** `x[i]` — доступ по индексу. Границы проверяются в рантайме
(bounds-check), как в Rust.

### 2.5. Операторы и выражения-конструкции

```
stmt        = "let" "mut"? ident (":" type)? "=" expr ";"
            | "let" "mut"? ident (":" type)? ";"              ; неинициализированное
            | expr "=" expr ";"                              ; присваивание
            | expr ";"
            | "return" expr? ";"
            | "if" expr block ("else" (if_stmt | block))?
            | "while" expr block
            | "for" ident "in" expr block
            | "break" ";"
            | "continue" ";"
```

`let` без `=` — значение без начального значения. Это нужно редко; тип
выводится из последующего присваивания. `void` означает «значения нет».

`mut` после `let` — переменная изменяемая. По умолчанию переменная
неизменяема: `let x = 5;` запрещает `x = 6;`. Это то же, что в V, и это
источник большинства сообщений компилятора у новичков.

Присваивание `expr = expr` разрешено только если левая часть — изменяемая
переменная или поле, достижимое через изменяемую ссылку.

**Нет тернарного оператора `?`** в v0: обработка ошибок через `match` и
явный `Result`. Тернарник добавится, когда будет понятно, как он должен
работать с владением.

### 2.5.1. Кто и что может менять

Три независимых понятия, которые легко спутать:

**1. Изменяемость переменной (`let mut`).** Только про переприсваивание
самой переменной: `x = 6` требует `let mut x`. Это локально и очевидно.

**2. Запись через ссылку (`&T`).** Ссылка в Keel **может** использоваться для
записи в то, на что указывает. Это и есть смысл group borrowing: несколько
ссылок на один объект могут писать в него одновременно, и это безопасно,
пока объект жив. Исключение Rust — «shared-xor-mutable» — снято намеренно.

```
let mut world = new_world();
let a = &world.entities[0];
let b = &world.entities[0];
a.hp = 50;      // запись через ссылку — разрешена
b.hp = 40;      // и вторая ссылка тоже
world.next_id = 7;   // переприсваивание — требует `mut` на переменной
```

**3. `mut`-контракт функции.** Это **не** система прав и **не** «функция
обязана что-то менять». Это объявление: «внутри этой функции изменяются
такие-то пути». Зачем: вызывающий должен знать, какие его ссылки стали
недействительными после вызова.

```
fn push(self &Vec<T>) mut(self) { ... }
// вызывающий:
let r = &vec[0];
vec.push(42);      // push модифицирует vec → всё внутри vec инвалидировано
// r.hp               // ошибка компиляции
```

То есть `mut` в сигнатуре — это информация **для компилятора**, а `let mut` —
это информация **для программиста**. Это разные вещи с разными последствиями,
и путать их нельзя.

Практическое следствие: `let x = 5;` запрещает `x = 6`, но
`let r = &x; r.field = 1` — не запрещает, потому что это запись в объект,
а не переприсваивание переменной. Если это окажется неудобным, правилом
может стать «через ссылку на неизменяемую переменную писать нельзя» —
вопрос вынесен в раздел «открытые вопросы».

### 2.6. Функции и модули

```
fn add(a int, b int) int { return a + b; }
fn noop() { }
fn void_ret() void { }
```

`main` — обычная функция с сигнатурой `fn main() int`. Тело функции может
не возвращать значение, если тип возврата `void` или не указан.

Имена модулей через `::` при импорте (v1): `import std::io::File;`.

`//` до конца строки и `/* ... */`. Вложенные `/* */` не поддерживаются.

### 2.8. Что НЕ входит в v0

Явно перечислено, чтобы границы были видны:

- лямбды и замыкания (нужны для `sort` по предикату, колбэков, обработчиков);
- трейты/интерфейсы и полиморфизм;
- дженерики для пользовательских типов (только встроенные `Vec<T>` и т.п.);
- макросы, `comptime`, шаблоны;
- массивы переменной длины, срезы;
- тернарный `?` и оператор `?` для `Result`;
- асинхронность (`async`/`await`) — требует соглашения о линейности
  футур (Higher RAII, п. 6), поэтому не раньше линейных типов;
- потоки и `Send`/`Sync`-подобные маркеры.

**`enum` больше не в этом списке** — он запланирован вместе с `match`
(раздел 7.2 дизайн-документа, пункт 10). Причина: правило о стабильности
формы (п. 3.6 раздела 3 дизайн-документа) различает мутацию содержимого и
мутацию формы, а варианты `Option`/`Result` имеют **разную форму** — один
носит значение, другой нет. Значит, `enum` нельзя выразить обычной
структурой с тегом: нужна отдельная форма объявления, а `match` по нему —
исчерпывающий разбор со всеми вариантами.

Запланировано также: `if` как выражение (связываемое значение) и `for`
по диапазонам и коллекциям. Для `for` по коллекции важно: он обязан
обходить *элементы*, а значит, опирается на group borrowing — и потому
служит проверкой модели, а не только удобством.

### 2.11. Открытые вопросы

Часть вопросов закрыта реализацией MVP (ноябрь 2026) — см. раздел 4
дизайн-документа. Ниже только те, что ещё открыты.

1. ~~Запись через ссылку на неизменяемую переменную.~~ **Решено частично.**
   Право писать определяется владельцем пути: локальная переменная — по
   `let mut`, параметр — по mut-контракту. То есть `let r = &x; r.f = 1`
   разрешено, если `x` объявлен как `mut`. Неизменяемость по умолчанию
   работает на уровне переменных, а не объектов.

2. **`mut`-контракт: выводится или задаётся?** Сейчас задаётся явно
   (`mut(world.entities[])`). Альтернатива — выводить из тела функции.
   Пока не решено; явный вариант проще, но требует дисциплины.

3. **Точность `mut`.** `mut(world.entities[])` — контракт на уровне
   коллекции. Точный вариант — `mut(world.entities[0])`. Сейчас работает и
   то, и другое, но переход от точного к грубому ломает инвалидацию у
   вызывающего, а это заметно. Нужно решить, что будет умолчанием.

4. **Тип возврата по умолчанию.** Сейчас `fn f() { ... }` без типа —
   возвращает `void`. Альтернатива — вывод типа возврата из тела.

5. **Явные дженерики.** `Vec<T>` встроен, но `fn f<T>(x T)` для
   пользовательских типов — вне v0. В MVP обобщённых типов нет вовсе,
   используются массивы `[T; N]`.

6. **`Option`/`Result` как структуры или как специальные типы.** Склоняюсь к
   обычным структурам.

7. **Диагностика.** Сейчас сообщение перечисляет пути, но не показывает
   цепочку инвалидации («здесь объявлено → здесь изменено → здесь
   использовано»). Это отдельная работа и отдельная ценность.

8. **Циклы.** Тело цикла проверяется двумя проходами — грубо, но ловит
   использование после инвалидации в следующей итерации. Обратный обход
   (как в Valen) дал бы точный результат.

### 2.12. Сводка отличий от C и Rust

| Конструкция | C | Rust | Keel |
|---|---|---|---|
| объявление | `int x;` | `let x: i32;` | `let x int;` |
| тип после имени | нет | до | да |
| изменяемость | всегда | `let mut` | `let mut` |
| ссылка | `int *` | `&` / `&mut` | `&` (одна вида) |
| ссылка на элемент | `&a[0]` | `&mut a[0]` | `a[0]` + путь в сигнатуре |
| lifetime | нет | `'a` | нет, выводится |
| возврат | `int f()` | `-> i32` | `fn f() int` |
| конструктор | нет | `S { f: v }` | `S(v)` |
| безопасность памяти | нет | да | да (в разработке) |

### 2.10. Полный пример

```keel
// Комментарий в стиле C.
import std::io::print;                      // v1

struct Entity {
    hp int;
    name string;
}

struct World {
    entities Vec<Entity>;
    next_id int;
}

fn new_world() World {
    return World(Vec<Entity>.new(), 0);
}

// Параметр-внутри: entity указывает на элемент world.entities.
// `mut` на параметре-внутри = «меняется содержимое world.entities».
fn damage(world &World, entity in world.entities[] mut, amount int) {
    entity.hp = entity.hp - amount;
    if entity.hp <= 0 {
        print("dead: ");
        print(entity.name);
    }
}

// Контракт мутации: функция меняет содержимое world.
fn spawn(world &World mut, e Entity) int {
    world.next_id = world.next_id + 1;
    world.entities.push(e);
    return world.next_id;
}

fn main() int {
    let mut world = new_world();
    spawn(world, Entity(100, "orc"));

    let e_ref = &world.entities[0];
    print(e_ref.name);

    // Две изменяемые ссылки на элементы одной коллекции — в Rust это ошибка.
    let a = &world.entities[0];
    let b = &world.entities[0];
    a.hp = 50;
    b.hp = 40;

    return 0;
}
```
